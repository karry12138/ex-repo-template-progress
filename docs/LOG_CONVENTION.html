过程文档约定（LOG CONVENTION）

目标：让每次打开项目都能秒懂「我在哪、上次到哪、下一步从哪继续」。 适用：本仓库所有进行中的工作（调查、实现、复现、骨架搭建等）。 机制来源：dk-incre（dk-incremental）实践沉淀而来。

1. 核心：两份文件

文件 作用 更新频率
docs/PROGRESS.md 当前锚点：我在哪/已完成/下一步/待拍板 每次有进展就覆盖更新
docs/logs/YYYYMMDD_HHMMSS_标题.md 时间轴：这次会话做了什么、背景、待办 每次有进展就新增一条

2. 命名约定（带时间戳）

  • 日志文件：docs/logs/<YYYYMMDD>_<HHMMSS>_<简短标题>.md
  • 示例：20260922_125733_进展机制.md
  • 时间统一用本地时区，文件头部写明 # 过程日志：YYYY-MM-DD HH:MM:SS 时区。

3. 引导提示模板（每条日志/锚点都要填）

## 1. 本次做了什么      —— 简短列出本次动作（带时间点）
## 2. 背景回顾          —— 回填一段上文，方便下次续接（分支、commit、上下文）
## 3. 待办 / 下一步      —— 明确勾选式待办 + 指向「从哪个文件/哪一步继续」
## 4. 可复用的关键路径    —— 常用文件/命令/分支，方便快速捡回上下文
## 5. 遗留 / 注意        —— 未处理项、风险、需人工确认的内容

4. PROGRESS.md 必填字段

⏱️ 最近更新    —— 时间 / 分支 / 本次做了什么
📍 当前进度    —— 一句话，写着「正在做…等待…」
✅ 已完成      —— 勾选式清单
⏭️ 下一步      —— 明确要做的动作 / 待拍板项（给建议）
🧭 快捷入口    —— 指向路线图/调查结论/日志
🗒️ 过程日志    —— 时间轴表格（时间/分支/说明/文件名）

5. 每次收尾时的动作

  1. 在 docs/logs/ 新增一条本会话时间戳日志。
  2. 覆盖更新 docs/PROGRESS.md 的「最近更新/当前进度/已完成/下一步/时间轴」。
  3. 若改了 README 的入口说明，保持 docs/PROGRESS.md 链接可用。
  4. （可选）git add docs/PROGRESS.md docs/logs/ && git commit，让进展跟随分支。

6. 为什么这么做

  • 时间戳：一眼看出记录新旧、辨别多次会话顺序。
  • 引导提示：不用靠记忆，打开就能从「下一步」无缝继续。
  • 锚点+时间轴分离：PROGRESS 看当前，logs 看历史，互不干扰。

7. md 与 html 的分工与生成

角色 文件 用途
执行依据 *.md 可 diff、版本管理、我执行时参考
阅读用 *.html（同名） 渲染后更轻松的阅读形式，你来看

每次会话收尾/开始时，若 md 有改动，用 tools/md_to_html.py --all-docs 重新生成 html。

python tools/md_to_html.py --all-docs   # 刷新 docs/ 下所有 md → html
python tools/md_to_html.py README.md    # 根目录 README

注意：html 是生成物，不要手工编辑；改内容改 md 再重新生成。

更新后的收尾动作（追加第 5 节条目 5）

  1. 若 md 有改动，用 tools/md_to_html.py --all-docs 刷新 html，并一起 git add/commit。
